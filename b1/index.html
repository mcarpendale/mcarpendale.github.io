Why I Moved My Blog to GitHub Pages

No paywalls, full ownership, and a workflow that actually makes sense for developers.

Medium had a good run. But paywall friction for readers, and zero ownership of my own content, finally pushed me to make the move.

Here’s what the setup looks like and why I’m not going back.

The Problem with Medium

When you publish on Medium, you’re essentially renting space. Your content is behind their paywall mechanics, their algorithm decides distribution, and if Medium changes its terms — you’re along for the ride.

For a developer writing about infrastructure and Kubernetes, this never made sense.

GitHub Pages: The Better Model

The stack is simple:

  • Private GitHub repo stores your Markdown source (nobody sees your drafts)
  • GitHub Actions builds the site on every push
  • Public GitHub Pages serves the compiled HTML

You get version control on every post, write in VS Code or any editor you prefer, and your readers hit zero friction.

The Workflow

Creating a new post is one command:

1

./new-post.sh b2 "My Next Post" "kubernetes,devops"

That scaffolds the file. You write. You push. GitHub deploys in ~30 seconds.

1
2
3

git add .
git commit -m "Add: My Next Post"
git push

Done.

What I Kept

Cross-posting back to Medium with a canonical URL pointing here. That keeps any existing audience while making your GitHub Pages site the source of truth for search engines.
